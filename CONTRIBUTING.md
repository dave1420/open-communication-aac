# Contributing

Thank you for helping make communication more accessible.

Before proposing a feature, explain the communication or access barrier it addresses and how a person using AAC was involved in identifying or evaluating it. Accessibility is a core requirement, not a later review phase.

## Ground rules

- Preserve adult dignity, agency, consent, and privacy.
- Never commit health information or identifying user data.
- Keep communication available offline.
- Avoid drag-only, gesture-only, double-tap-only, and long-press-only interactions.
- Use native semantic controls and maintain a logical focus order.
- Add tests for behavior changes.
- Document licences and attribution for every third-party asset.

## Before opening a pull request

```powershell
npm test
npm run build
npm run format:check
```

Describe manual checks for touch, keyboard, narrow layouts, high contrast, and reduced motion when relevant.
